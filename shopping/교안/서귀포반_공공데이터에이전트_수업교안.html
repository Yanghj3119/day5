수업 1

오늘 쓴 두 API — 주소 모양 다시 보기

30분
🎯 공공데이터 두 개를 도구 두 개로 만든다. 먼저 주소 모양을 정리한다 — 끝점 / 오퍼레이션 ? 인증키 & 조건들.
💡 쉽게 말하면

API 는 정보를 주문하는 창구예요. 주소 한 줄이 곧 주문서 — “어느 창구(끝점) / 무엇을(오퍼레이션) ? 출입증 & 몇 쪽 & 몇 줄 & 어떤 모양(JSON)” 순서로 적어요.

🙋 왜 하나요?

주문서를 읽을 줄 알면, 어떤 공공데이터든 같은 방법으로 도구가 돼요. 오늘 두 개, 과제에서 두 개 — 모두 이 모양이에요.

따라하기

복사해서 쓰는 프롬프트 (빨간 글자만 내 것으로 바꿔도 돼요)

주소 두 개 정리 (Plan 모드)
Plan 모드야. 파일은 건드리지 말고 정리만 해줘.
공공데이터 두 개를 에이전트 도구로 쓰려고 해.
① 기상청 단기예보: https://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getVilageFcst
   조건: serviceKey · pageNo=1 · numOfRows=1000 · dataType=JSON · base_date · base_time · nx=52 · ny=33 (서귀포 격자)
② 제주 공공데이터: https://api.odcloud.kr/api/15125100/v1/uddi:여기에-Swagger-GET-경로 ?page=1&perPage=300&serviceKey=…
각 주소에서 받는 값(칸 이름)과, 인증키를 코드에 쓰지 않고 Vercel 환경변수 DATA_GO_KR_KEY 로 읽는 방법을 쉬운 말로 정리해줘.
🧭 알아 두면 덜 막혀요
  • 물음표(?) 앞은 “어디로”, 뒤는 “어떤 조건으로”예요.
  • 조건과 조건 사이는 &(그리고)로 이어요.
  • 단기예보는 dataType=JSON, 다른 API 는 _type=json · returnType=json 처럼 이름이 달라요 — 참고문서에 적힌 이름 그대로.
수업 2

도구 ① get_forecast — 기상청 단기예보

40분
🎯 서귀포 오늘 · 내일 강수확률 · 기온 · 하늘을 기상청 예보로 가져오는 도구를 만든다. 발표 시각(base_time)과 실패했을 때의 답까지.
💡 쉽게 말하면

도구 ① 은 “서귀포 내일 날씨 알려 줘” 라고 기상청 창구에 주문서를 내는 손이에요. 기상청은 하루 8번(02 · 05 · 08 … 23시) 예보를 새로 내니까, 가장 최근 발표분을 달라고 적어요.

🙋 왜 하나요?

에이전트가 “비가 오나?”를 지어내지 않고 진짜 숫자(강수확률)를 보고 판단하게 하려고요.

따라하기

복사해서 쓰는 프롬프트 (빨간 글자만 내 것으로 바꿔도 돼요)

도구 ① 만들기
api/agent.js 에 get_forecast 도구를 만들어줘.
- 입력: area(서귀포 · 제주시), day(오늘 · 내일)
- 기상청 단기예보 getVilageFcst 를 불러, base_time 은 지금 시각 기준 가장 최근 발표(02 · 05 · 08 · 11 · 14 · 17 · 20 · 23시, 10분 뒤 제공)로
- 서버는 UTC 라서 한국 시간(+9)으로 계산
- 결과: 그날 강수확률 최댓값(POP) · 최고/최저기온(TMP) · 하늘(SKY 1 맑음 · 3 구름많음 · 4 흐림) · 출처(발표 시각)
- 인증키는 process.env.DATA_GO_KR_KEY 만, 실패하면 { ok:false, note } — 숫자를 지어내지 마. 도구 설명(input_schema)도 같이.
직접 불러 보기
tools_test.html 을 만들어서 get_forecast 를 지역 · 날짜 골라 불러 보게 해줘. 서귀포 내일 결과와 출처를 알려줘.
🧭 알아 두면 덜 막혀요
  • nx · ny 는 지도 위 바둑판 칸 번호예요 — 서귀포 52 · 33, 제주시 53 · 38.
  • POP = 강수확률, TMP = 기온, SKY = 하늘(1 맑음 · 3 구름많음 · 4 흐림).
  • “가져오지 못했어요”가 나오면 정상이에요 — 숫자를 지어내지 않았다는 뜻!
수업 3

도구 ② search_jeju_data — 제주 공공데이터

40분
🎯 15125100 데이터에서 낱말이 들어 있는 줄을 찾는 도구를 만든다. 칸 이름은 데이터마다 다르니, 처음엔 전체를 보고 칸 이름부터 확인한다.
💡 쉽게 말하면

도구 ② 는 제주 데이터 표에서 낱말로 줄을 찾는 손이에요. 엑셀에서 Ctrl+F 로 찾는 것과 같아요.

🙋 왜 하나요?

데이터마다 칸 이름이 달라서, 처음엔 칸 이름부터 보는 것이 요령이에요. 칸을 알아야 좋은 질문을 할 수 있어요.

따라하기

복사해서 쓰는 프롬프트 (빨간 글자만 내 것으로 바꿔도 돼요)

도구 ② 만들기
api/agent.js 에 search_jeju_data 도구를 만들어줘.
- 주소: https://api.odcloud.kr/api + process.env.ODCLOUD_PATH + ?page=1&perPage=300&returnType=JSON&serviceKey=…
- 입력: keyword(찾을 낱말, 띄어쓰기로 여러 개), limit(기본 8)
- 응답의 data 배열에서 어느 칸이든 낱말이 들어 있는 줄을 찾아 돌려줘(전체 줄 수 · 찾은 줄 수 · 칸 이름 목록 포함)
- 위도 · 경도 칸이 있으면 지도용 좌표로 따로 꺼내 둬(제주 범위 밖이면 버리기)
- 실패하면 { ok:false, note }. 도구 설명에 ‘표 밖의 내용은 없다’를 넣어줘.
칸 이름 보기
search_jeju_data 를 낱말 없이 불러서 칸 이름 목록과 첫 3줄을 보여줘. 이 데이터로 서귀포 여행자에게 답할 수 있는 질문 3개를 제안해줘.
🧭 알아 두면 덜 막혀요
  • ODCLOUD_PATH 는 Swagger 의 GET 경로 — /15125100/v1/uddi:… 처럼 생긴 글자예요.
  • 위도 · 경도 칸이 있으면 3D 지도에 핀이 찍혀요. 없으면 카드만 나와도 괜찮아요.
수업 4

에이전트 — 도구 고르기 · 판단 규칙 · 3D 지도

50분
🎯 Claude 가 두 도구를 골라 쓰고, 결과를 보고 다시 판단하는 반복(최대 5번)을 만든다. 판단 규칙을 넣고, three.js 3D 지도에 핀을 찍는다.
💡 쉽게 말하면

에이전트는 도구 두 개를 쥔 길잡이예요. 질문을 보고 → 도구를 골라 부르고 → 결과를 보고 → 다시 판단해요. 이 반복을 최대 5번까지.

🙋 왜 하나요?

판단 규칙(“강수확률 50% 이상이면 실내”)을 적어 두면, 답이 왜 그렇게 나왔는지 숫자로 설명돼요.

따라하기

복사해서 쓰는 프롬프트 (빨간 글자만 내 것으로 바꿔도 돼요)

에이전트 반복 + 판단 규칙
api/agent.js 에서 Claude Messages API 에 tools(get_forecast · search_jeju_data)를 넘기고, 도구 요청(tool_use)이면 실행해서 결과(tool_result)를 돌려주고 다시 물어봐. 최대 5번.
판단 규칙: ① 강수확률 50% 이상이면 실내 · 가까운 곳 위주 ② 데이터 표에 없는 장소는 추천 금지 ③ 날씨를 못 가져오면 그렇다고 말하기 ④ 운영시간 · 요금 단정 금지
도구를 부를 때마다 steps 에 한 줄씩 남기고, 최종 답은 JSON {items:[{name,why}], judge, tip}. items 는 데이터와 대조해 좌표 · inList 를 붙여.
열쇠는 process.env.ANTHROPIC_API_KEY 만, 없으면 연습 모드(날씨 → 데이터 → 규칙 순서).
3D 지도 연결
index.html 에서 /api/agent 답을 이렇게 보여줘:
① judge 한 줄(보라) ② three.js(cdnjs three.js r128)로 제주 섬 3D 지도 — 섬 모양은 근사, 한라산은 원뿔, items 좌표에 번호 핀이 위에서 떨어지게, 끌어서 돌리기 · 가까이 / 제주 전체 버튼
③ 카드(번호 · 이름 · 데이터에 있음/없음 · 이유) ④ 생각 과정 보기(찾기 파랑 · 판단 보라 · 실행 초록)
지도 위에 강수확률 · 하늘 · 최고기온 작은 표시. 지도는 마지막 답 하나만 움직이고 이전 지도는 사진으로 바꿔 둬.
🧭 알아 두면 덜 막혀요
  • 생각 과정 보기를 펼쳐 보세요 — 파랑(찾기) · 보라(판단) · 초록(실행)이 차례로 나와요.
  • 핀 번호 = 카드 번호. 다르면 “번호를 맞춰 줘”라고 부탁해요.
  • 데이터에 없는 장소가 나오면 “데이터 없음”으로 표시돼요 — 규칙 ② 가 일하는 중!
수업 5

배포 — 환경변수 3개 · 휴대폰으로 물어보기

20분
🎯 열쇠 점검 → 세이브 → 배포. Vercel 환경변수 3개(DATA_GO_KR_KEY · ODCLOUD_PATH · ANTHROPIC_API_KEY)를 넣고 휴대폰으로 확인한다.
💡 쉽게 말하면

인증키는 출입증이라 화면 코드에 쓰면 누구나 훔쳐 갈 수 있어요. 그래서 서버의 비밀 칸(환경변수)에 넣어요.

🙋 왜 하나요?

화면(휴대폰) → 우리 서버(출입증 붙이기) → 공공데이터. 출입증은 서버 밖으로 나가지 않아요.

따라하기

복사해서 쓰는 프롬프트 (빨간 글자만 내 것으로 바꿔도 돼요)

배포
1) 폴더 · 세이브 포인트에 API 키처럼 보이는 문자열이 없는지 점검(값은 보여 주지 말 것)
2) 세이브 포인트: '서귀포 공공데이터 에이전트 — 도구 2개 · 3D 지도'
3) GitHub 에 올리고 프로덕션 배포
4) 배포 주소에 내일 서귀포에서 갈 만한 곳 을 보내서 mode 가 ai 인지, 생각 과정에 날씨 · 데이터 찾기가 나오는지 확인
🧭 알아 두면 덜 막혀요
  • 환경변수 3개: DATA_GO_KR_KEY(공공데이터 출입증) · ODCLOUD_PATH(제주 데이터 경로) · ANTHROPIC_API_KEY(Claude 출입증).
  • 환경변수를 넣은 뒤에는 다시 배포해야 반영돼요.
  • 계속 “연습 모드”면 /vercel-logs 로 어디서 실패했는지 봐요.
